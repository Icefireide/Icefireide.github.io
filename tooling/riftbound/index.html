Riftbound Broadcast Overlay

The on-air overlay for Riftbound tabletop broadcasts — persistent side columns, a shared victory track, and structural gaps left open for the player cameras.

This is the real thing. The stylesheet and the render code on this page are byte-for-byte copies of the production tool, unmodified. What stands in is the transport: instead of the tool’s WebSocket feeding state and its API serving client branding, the buttons below push the same snapshots through the same code path. Nothing here is a mockup of the overlay — it is the overlay.

Victory points cap at 8 per side — the track is the only place they render, deliberately never also as a numeral, so the same number can never be shown two ways that disagree mid-change.

The centre is empty on purpose

No overlay element exists in the middle of the canvas at all. A board camera and a digital capture are the same empty box to this page, so one layout serves both without a mode switch.

The camera gaps are real absence

Each column is two separate opaque panels with genuinely nothing between them, not a transparent-styled element. Turn the cameras off and the panels close up rather than leaving a framed hole.

Themed per client

Every colour comes from a token resolved from the active client profile. Cycling the palette here runs the same branding path a profile switch runs on air.

Nothing is rebuilt

Every element is created once. Updates only ever touch text, a class, or an attribute — so the overlay can never flicker or tear down mid-show.
